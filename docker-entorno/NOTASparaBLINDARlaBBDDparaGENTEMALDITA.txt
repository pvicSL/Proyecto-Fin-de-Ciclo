1. El Bloque SQL "Invencible" (Para tu script db-init)

Busca el archivo donde tienes el script que crea las tablas (db-init.sql o como se llame en tu proyecto). Borra las líneas donde creas la base de datos y sustitúyelas por este bloque al principio de todo el archivo.

Esto asegura que la "casa" (la BBDD) se construya con soporte para caracteres especiales antes de meter ningún mueble (tablas) ni inquilinos (datos).



-- 1. Borrar si existe (limpieza total)
DROP DATABASE IF EXISTS estudio_tatuajes;

-- 2. CREAR CON SOPORTE UTF-8MB4 (El "Blindaje")
-- utf8mb4 permite tildes, ñ, e incluso emojis.
CREATE DATABASE estudio_tatuajes
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- 3. USAR LA BASE DE DATOS
USE estudio_tatuajes;

-- A partir de aquí, pon tus CREATE TABLE normales.
-- Al haber definido la BBDD en utf8mb4, las tablas heredarán esa configuración automáticamente.

2. Configuración del Contenedor (Docker Compose)

Si levantas la base de datos con docker-compose, hay un truco extra. A veces, aunque el script SQL esté bien, el servidor MySQL del contenedor arranca en inglés (Latin1) y puede haber conflictos en la negociación.

Añade la línea command en tu archivo docker-compose.yml dentro del servicio de mysql:

version: '3.8'
services:
  mysql_db:
    image: mysql:8.0  # O la versión que uses
    container_name: mysql_tatuajes
    # ... tus puertos y variables de entorno ...
    
    # AÑADE ESTA LÍNEA MÁGICA:
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci

    # ... volúmenes, etc …

¿Por qué esto es la solución definitiva?

    Docker (command): Obliga al servidor MySQL a "pensar" en UTF-8 desde que arranca el proceso.

    SQL (CREATE DATABASE): Obliga a que el almacén de datos acepte UTF-8.

    Java (application.properties): (Que ya lo tienes) Obliga a que la tubería de datos transporte UTF-8.

Con estos tres puntos alineados, la próxima vez que hagas un reset de tu entorno, todo funcionará a la primera, sin necesidad de comandos ALTER ni parches manuales.
